## Persistence checkpoint and rollback

An owner-only checkpoint contains the previous runtime definitions, immutable
image identities, Media Manager work, and sidecar metadata. The two archives total
27,057,152 bytes and passed archive and checksum checks. No private archive or
runtime file is committed. The previous Media Manager image started healthy in
a disposable networkless container against a separate restored copy, preserving
all four original records. The verification container was removed; the private
checkpoint and isolated restored copy remain on the host.

Use the current Compose files plus `compose.downloads.yaml` for Media Manager;
use the existing sidecar deployment files plus its protected `compose.bridge.yml`.
Keep the old images and protected runtime definitions until acceptance is complete.

For rollback, first stop acceptance, stop both application workers, and checkpoint
**the latest** work and sidecar metadata. Preserve the new work directory intact,
including pending jobs and imported originals. Use a separate pre-release restored
work directory with the old image/configuration; never allow the older startup
cleanup to see newly accepted pending records. Keep the newer directory available
for restoration with this release. Draining accepted work or a forward fix is
preferred because rollback to the old UI does not expose newer pending workflows.
See [the persistence compatibility procedure](deployment.md#rollback).

## Remaining separate gates

Telegram is disabled pending bot creation and private application/chat/user
configuration plus live acceptance. Replacement credential-free Shortcut files
are committed but were not signed or installed during this deployment. Existing
installed versions retain their old cleanup behavior; replacing them is required
for the revised timeout/error/success retention behavior. Physical
iPhone locking, native share/save behavior, and Home Screen acceptance remain
separate from automated browser/server checks. A phone-side download interrupted
by device suspension remains retryable from history; server execution is independent.
